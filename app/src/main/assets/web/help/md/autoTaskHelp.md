# 定时任务帮助

定时任务由五字段 Cron 驱动，按计划执行一段同步 JavaScript；脚本的最终返回值按「返回协议」解析为动作（更新目录 / 发通知）。脚本环境与书源规则一致（`java.*` 可用），并复用登录、Cookie 与缓存能力。

## Cron 表达式

格式：`分 时 日 月 周`，五字段、以空格分隔。按设备本地时区运行，最小粒度一分钟。

| 表达式 | 说明 |
|--------|------|
| `*/5 * * * *` | 每 5 分钟 |
| `0 9 * * *` | 每天 09:00 |
| `0 9 * * 1` | 每周一 09:00 |
| `0 0 1 * *` | 每月 1 日 00:00 |
| `0 8,20 * * *` | 每天 08:00 和 20:00 |
| `*/30 6-23 * * *` | 06:00～23:00 之间每 30 分钟 |
| `30 9 1-7 * 1` | 每月 1～7 日的 09:30，以及每个周一的 09:30 |

符号：

- `*` 任意值；`?` 同 `*`
- `,` 列表（多个值）
- `-` 范围
- `/` 步长

取值范围：分 `0-59`，时 `0-23`，日 `1-31`，月 `1-12`，周 `0-7`（周日可写 `0` 或 `7`）。

> 日与周同时受限时按 **OR** 匹配，不是 AND：`30 9 1-7 * 1` 匹配「每月 1～7 日的 09:30」或「每个周一的 09:30」，而不是只匹配两者交集的时刻。

## 返回协议

脚本需要返回 **JSON**，支持三种形态：

**1. 动作数组**
```json
[
  { "type": "refreshToc", "bookUrl": "https://..." },
  { "type": "notify", "title": "完成", "content": "全部更新完毕" }
]
```

**2. 单个动作对象**（须含 `type`）
```json
{ "type": "notify", "title": "签到", "content": "已签到 {time}" }
```

**3. 包裹在 actions 中**
```json
{
  "actions": [
    { "type": "refreshToc", "bookUrl": "https://..." }
  ]
}
```

返回 null 或无法解析时视为无动作，不报错。

## 支持的动作

### type: refreshToc — 更新书籍目录

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | string | ✓ | `"refreshToc"` |
| `bookUrl` | string | ✓ | 书架中书籍的绝对 bookUrl，按此精确匹配 |
| `notify` | object | | 更新通知配置；不写则更新后不发通知 |
| `cache` | object | | 自动缓存新章节配置 |

**notify 子对象**（存在时下列字段可选、缺省值生效；无新增章节时不发通知）：

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `enable` | boolean | true | 是否发通知 |
| `minCount` | number | 1 | 至少新增多少章才通知 |
| `title` | string | 内置文案（随界面语言） | 通知标题，支持占位符 |
| `content` | string | 内置文案（随界面语言） | 通知内容，支持占位符 |

**cache 子对象：**

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `enable` | boolean | false | 是否自动缓存新章节 |

**完整示例：**
```json
{
  "type": "refreshToc",
  "bookUrl": "https://example.com/book/123",
  "notify": {
    "enable": true,
    "minCount": 5,
    "title": "《{book}》更新了！",
    "content": "作者 {author} 新增 {newCount} 章\n最新：{chapter}\n时间：{time}"
  },
  "cache": {
    "enable": true
  }
}
```

---

### type: notify — 发送通知

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | string | ✓ | `"notify"` |
| `title` | string | | 通知标题，默认「任务通知」 |
| `content` | string | | 通知内容，默认任务名 |
| `level` | string | | 优先级：`high`/`error`/`fail`/`failed` 为高，`low` 为低，其余为普通 |
| `id` | number | | 通知分组 id，相同 id 的通知互相替换；缺省按任务名+标题+内容生成稳定 id |

```json
{
  "type": "notify",
  "title": "每日签到",
  "content": "已完成\n时间：{time}",
  "level": "high",
  "id": 1
}
```

---

## 占位符

**refreshToc 通知中可用：**

| 占位符 | 替换为 |
|--------|--------|
| `{book}` | 书名 |
| `{author}` | 作者 |
| `{newCount}` | 新增章节数 |
| `{chapter}` | 最新一章标题 |
| `{time}` | 当前时间（MM-dd HH:mm） |

**notify 通知中可用：**

| 占位符 | 替换为 |
|--------|--------|
| `{task}` | 任务名称 |
| `{time}` | 当前时间（MM-dd HH:mm） |

---

## 任务字段

编辑页可配置：名称、启用开关、Cron、脚本、备注；请求与登录环境字段：请求头、jsLib、并发率、登录URL/登录UI/登录检查JS、启用CookieJar（与书源同语义）。脚本可直接写 JavaScript，也兼容外层 `@js:` 或 `<js>...</js>` 包裹。运行状态字段（上次运行时间/结果/错误/日志）由应用维护，导入时无需填写。

## 调试与导入

- 编辑页右上角菜单 →「调试」：单次运行当前脚本并在对话框查看执行日志。
- 管理页支持导入/导出任务 JSON；定时任务服务开关在设置中开启后才会按 Cron 调度。

## 自动任务停止时如何反馈

自动任务服务会独立记录基础诊断，**无需提前开启“记录日志”**。发生不再自动执行的问题时，尽量先保存日志，再关闭/开启自动任务，以保留停止现场：

1. 记下最后一次正常执行时间，以及后续未执行的定时点。
2. 在“关于 → 保存日志”导出到已设置的备份目录，将 `logs.zip` 提供给维护者。如果提示未开启记录日志，基础自动任务诊断仍会被打包；该开关控制的是更完整的调试日志。
3. 同时提供 Android 版本、应用版本和任务线程数。需要进一步排查书源时，再开启“其它设置 → 记录日志”复现并导出。

基础诊断文件为 `logs/auto-task-diagnostic.log` 和 `logs/auto-task-diagnostic.previous.log`，各最多约 512 KiB，总计约 1 MiB，自动轮换。应用内日志列表也能看到 `[AutoTaskDiag]` 条目，但列表只保留最近部分记录，批量任务反馈应优先提供文件日志。

关键事件：

| 事件 | 含义 |
| --- | --- |
| `dispatch.request` / `dispatch.failed` | 手动或应用内启动/刷新/停止请求，以及进入服务之前的启动失败 |
| `service.create` / `service.start_command` | 服务实例和触发来源；闹钟触发含预约时间与送达延迟 |
| `service.foreground_started` / `service.foreground_denied` | 成功进入前台或被系统拒绝，同时记录相关权限状态 |
| `alarm.scheduled` / `alarm.schedule_failed` | 下一次闹钟预约结果及精确/非精确模式；预约成功不等于系统已经送达 |
| `batch.begin` / `batch.end` | 本批到期数、并发上限、已开始/完成/失败/中断/未开始数量 |
| `task.begin` / `task.stage` / `task.end` | 每项任务的开始、脚本/动作/保存阶段和终态，避免只看到上一项完成 |
| `service.heartbeat` | 运行期间约每 30 秒的快照，含仍在运行的任务及耗时 |
| `service.timeout` / `service.destroy` | 系统超时和服务销毁时的未完成任务快照 |

`completed` 表示任务执行尝试已经返回，不保证每个 `refreshToc` 动作都成功；更新结果仍需看任务动作日志。任务取消不会被伪记为成功，也不会覆盖其上次完成时间。心跳是诊断，不是保活或重试机制；设备休眠或进程被冻结时不保证按时输出。

基础诊断只额外记录任务 ID/名称、Cron、计数、执行阶段、时间、权限和异常类型，不额外记录脚本、Cookie、请求头、请求正文、返回内容或异常消息。任务名可能包含书名，分享前可检查；可选的完整调试/HTTP 日志可能包含更多敏感内容。

诊断通过独立单线程、有界队列异步写入；队列过载时保留较新的事件，并记录 `droppedBeforeWrite`。进程突然被杀仍可能丢失少量尚未落盘的尾部记录；磁盘不可写、清理缓存也会影响留存。Android 15 及以上使用的短前台服务仍有约三分钟的单次时限。

## 漏唤醒恢复（Android 15 及以上）

- Cron 主闹钟由独立广播接收器接收，再显式启动前台服务；日志中 `alarm.delivery` 表示广播进入应用，`alarm.received` 表示该预约通过代次校验，`service.start_command` 表示已进入任务服务。可以区分闹钟未送达和服务启动失败。
- 每个主闹钟额外预约约 **5 分钟后**的恢复闹钟。正常唤醒后会替换旧恢复预约，不会因为增加恢复闹钟就多执行一次同批任务。系统休眠、配额或厂商限制仍可能使它延迟。
- 接收唤醒后，**先预约五分钟后的重试，再尝试启动服务**；因此前台启动被拒绝、初始化未完成、服务异常退出时，不再只依赖这次服务安排下一次。服务进入任务扫描后按实际 Cron 替换该重试计划。
- 回到前台或进程重建后，会在后台线程检查预约是否缺失、过期或之前启动失败；检查有节流且跳过存活服务，不在页面恢复回调中读取任务数据库、执行脚本或进行网络请求。通常不必再手动关闭/开启自动任务。
- 主闹钟和恢复闹钟使用同一代次校验；过期、重复广播不执行任务。关闭“自动任务”会取消两类预约与旧版服务闹钟，晚到广播也会检查开关。
- 重启设备、升级应用、调整系统时间/时区或重新授予精确闹钟权限后，仅对已开启自动任务的设备重新预约唤醒；接收系统广播时不直接执行脚本。
- Android 11 及以上进程启动时可记录 `process.exit_history` / `process.exit_reason`，包括系统给出的退出时间、原因、PID和内存统计。不读取退出描述、堆栈或转储；若系统没有记录、原因未知或记录已淘汰，不能据此断言厂商杀后台。

以上是恢复机制，不是永久保活，也不保证绕过系统强行停止、厂商后台冻结或精确闹钟限制。按 Cron/上次完成时间重新检查到期任务，**不补跑每一个历史时点**，不改变原有任务并发与去重规则。再次出现停顿时先导出日志，说明是普通切回前台，还是划掉后台、强行停止后重开；仅“切回来卡一下”不能单独证明退出原因。
